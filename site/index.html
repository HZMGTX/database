The central bet

Everything is one row in one table.

A note, a task, an invoice line and a fish from a game's item catalogue are the same shape: an id, a kind, a title, a body, a JSON bag of properties, timestamps and a revision number. That is what lets search, tagging, linking, versioning, trash, undo, import and export each be implemented exactly once.

The five kinds with real invariants — task, event, link, file, person — get a facet table joined on a composite key, so “an event has a start time” is enforced by the database itself, from the CLI, the API, the browser or hand-typed SQL. Everything else is a JSON property, projected by trigger into a typed, indexed column. A field you invent on Tuesday is range-queryable on Wednesday, with no migration.

Capture is one line

vault add "call the plumber" and it is in. Kind, tags, due dates and properties are all optional and can be added later, or never. Untidy capture still turns up in search, which is the point.

Nothing is lost

Every write stores a compressed snapshot of the whole document plus a transaction-scoped audit row. vault undo reverses the last change however many items it touched — a 200-item bulk retag included.

Leaving is designed for

Export to JSONL, Markdown, CSV, iCalendar, or one self-contained HTML file that opens from a USB stick on a machine with no Python and no network. vault diff-db proves a round trip was lossless.

Three interfaces, one engine

A CLI for the keyboard, a REST API with ETags and optimistic concurrency for scripts, and a web UI served from the same process. They share the single write path, so none of them can corrupt what the others wrote.

Connects, doesn’t replace

It reads another application’s SQLite database on a mode=ro connection and indexes it alongside your own notes. Your existing app keeps its data layer, untouched, and keeps running while Vault reads.

Secrets stay out

The repository indexer excludes credentials structurally: a file that trips the scanner is indexed by path and metadata only, never content, and vault doctor lists what was withheld.

Search is the product

A query language you can actually type.

FTS5 with BM25 ranking over four weighted columns — a hit in the title counts for more than one in the body — plus a trigram index for substrings and typos. Filters compile to parameterised SQL predicates; no text you type is ever concatenated into a query. 

# both words, ranked
vault find budget review

# a phrase, and an exclusion
vault find "exact phrase" -draft

# facets and tag subtrees
vault find kind:task status:todo,doing
vault find tag:work/*

# dates, in your zone, not UTC's
vault find due:today
vault find starts>2026-10-01

# any property, through the typed projection
vault find rarity:Legendary value>5000

# structure
vault find is:orphan has:file sort:recent

Measured, not asserted

On 100,000 documents with a Zipf-distributed vocabulary, median of seven runs. Cost tracks how many documents a term matches, which is what ranked search fundamentally has to score.

No cap is applied to hide the last row. Truncating the candidate set before ranking was tried and rejected: FTS5 scores every match either way, so it buys nothing measurable while silently dropping results.

What it does not do. There is no semantic search. Real embeddings need a model download or an external API, and both are ruled out by the zero-dependency, works-offline promise. What ships is BM25 ranking, trigram fuzzy matching and synonym expansion — genuinely strong lexical search, which is not the same thing. A provider seam exists and is deliberately empty.

How it was built

The corrections are the interesting part.

The first design of this schema looked fine and contained four defects that would each have shipped silently. They were found by running them, not by reading them, and every one now has a named regression test.

  1. The search box that failed on ordinary prose

    The tokenizer was configured with tokenchars '_@.-', to keep URLs and filenames whole. It also made the full stop part of a word, so searching budget against “Please review the budget.” returned zero results. So did known against “well-known”.

  2. The integrity check that checked nothing

    The cheap form of FTS5’s integrity-check passes happily after the content table has changed underneath the index. The entire correctness safety net rested on it. It is now the content-aware form, everywhere, and a test corrupts the table on purpose to prove the check catches it.

  3. Short IDs that were not distinct

    Short handles took the first eight characters of a UUIDv7. The first twelve characters of a UUIDv7 are a millisecond timestamp: 2,000 identifiers generated in a burst shared a single prefix. Handles now come from the tail, with an index to match.

  4. The audit trigger that blocked deletion

    An audit column referenced the table it audited with ON DELETE SET NULL, while a trigger inserted the row being deleted. SQLite runs the foreign-key action first, so every hard delete failed. An append-only ledger must not hold a reference to the thing it is recording.

There were twenty-two more. A linting test mechanically enforces the three invariants the whole design rests on: sqlite3.connect appears in exactly one module, no SQL is ever built by string formatting, and nothing outside the standard library is imported.

Getting it

Clone, run, done.

There is no install step, because there is nothing to install. Python 3.9 or newer is the only requirement, and it ships with SQLite. 

git clone https://github.com/hzmgtx/database.git
cd database

# create the database and open the web UI
./vault

# or stay in the terminal
./vault demo
./vault find budget
./vault today

# put it on your PATH
./vault install-cli

Where your data lives

data/vault.db, inside the repository, ignored by git so it is never committed. Override it with --db or $VAULT_DB.

To back it up: vault backup takes a verified snapshot while the server is running. Or stop the server and copy the file. Both work, and the second one is the reason the design is a single file at all.

The file is not encrypted. It is a plain SQLite database, and disk encryption is the right answer to that.
